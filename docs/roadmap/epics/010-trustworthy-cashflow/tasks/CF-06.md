## Acceptance Criteria

- [ ] Only established internal movements between linked accounts are excluded from realized income and expense; uncertain candidates remain counted and reviewable.
- [ ] Verify checking-to-checking, linked card repayment, and linked payment-account funding without relying on account ownership or a fixed account-type whitelist.
- [ ] Same-size unrelated transactions and ambiguous competing matches cannot silently hide real expenses. Prevent a transaction from belonging to incompatible pairs.
- [ ] Matching respects opposite direction, account identity, posting-date tolerance, and currency; never infer exchange conversion from matching nominal amounts.
- [ ] Confirm, reject/unpair, and manual pairing have explicit reversible effects. Rejected candidates stay rejected after detection or sync unless evidence/user action legitimately changes the decision.
- [ ] Source changes or deletion invalidate stale relationships; new counterpart history can reconcile past activity and update reports.
- [ ] API validation rejects invalid pairs with useful errors. Preserve enough paired-transaction evidence for review and drill-down.
- [ ] Add tests for the positive cases, false-positive collisions, competing matches, repeated detection, and persisted corrections.
