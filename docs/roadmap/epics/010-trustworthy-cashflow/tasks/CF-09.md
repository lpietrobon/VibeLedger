## Acceptance Criteria

- [x] Existing attention counts and review queues lead to the same eligible records, including matches beyond the first fetched page.
- [x] Users can inspect the evidence for a questionable classification, transfer candidate, or available duplicate/suspicious-charge hint, then correct or dismiss it through a small clear workflow.
- [x] The UI distinguishes a replayed import from two actual charges; reviewing or dismissing a suspicion does not erase a real transaction or exclude it from totals.
- [x] Confirm/reject, recategorize, and reviewed-state actions persist through refresh and resync, with visible success/error feedback and correct downstream totals.
- [x] Existing subscription counts, active/canceled overrides, cadence, and cost estimates are consistent and traceable to eligible posted transaction evidence; label estimates and limited history honestly.
- [x] Internal transfers and refunds do not become subscriptions; same-size purchases are not declared duplicate services without evidence.
- [x] Fix gaps in the existing review flow identified by CF-03 and add regression tests. If a requested suspicion type has no existing detection support, document the gap and a separate scope decision rather than implying it is detected.
- [x] Keep the scope to useful existing review and recurring behavior; no new trial-conversion, forecasting, generalized fraud, or optimization subsystem.
