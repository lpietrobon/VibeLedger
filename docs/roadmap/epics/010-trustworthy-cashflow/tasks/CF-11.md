## Acceptance Criteria

- [ ] Monthly/yearly totals, comparison labels, category breakdowns, and clicked transaction evidence agree with the independently verified accounting fixture.
- [ ] A spending increase can be explained without an internal transfer, duplicate import, pending charge, or stale cache masquerading as new expense.
- [ ] Check incomplete history, no activity, unusually large/negative category values, loading/failure states, and narrow/mobile layouts; the UI never substitutes an unsupported conclusion for missing data.

- [ ] Confirm basic keyboard access and understandable labels for the changed controls; inspect both supported dashboards without demanding cosmetic parity.
- [ ] Record remaining UX defects with severity and reproduction steps. Reverify fixes; distinguish actual user validation from expert walkthrough conclusions.
- [ ] The accepted result answers the epic's spending/trust questions without requiring routine manual bookkeeping or making synchronization status the main experience.
