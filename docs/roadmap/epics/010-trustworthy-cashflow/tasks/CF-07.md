## Acceptance Criteria

- [x] Income, expense, net cashflow, categories, period summaries, and transaction drill-downs follow the CF-02 accounting contract and agree on contributing rows.
- [x] Realized totals use posting dates, exclude pending activity, and use the agreed distinction between internal transfers and unresolved candidates.
- [x] Refund handling is consistent across totals and categories, including later-period refunds and refund-only negative categories; uncertain reimbursements do not silently reduce expense.
- [x] User category corrections, supported rules, and fallback categories follow one documented precedence and remain stable across sync/recomputation.
- [x] API results and the effective SQL/dashboard view agree for the same scope. Shared deterministic functions or existing service/query paths express the policy without a second independent money calculation in the client.
- [x] Existing API/filter paths can retrieve the rows explaining a displayed aggregate, including beyond the first page; optional agents can query those paths without ingesting the ledger.
- [x] Corrections and new counterpart history update affected historical totals; unsupported mixed-currency aggregation is not presented as a meaningful combined amount.
- [x] Add parity and edge-case tests with hand-calculated results. Integrate against CF-05/CF-06 before final verification; do not introduce unrelated API or analytics infrastructure.

### 2026-09-06 — acceptance closure

Reporting now uses CF-02 calendar-aligned month-to-date and year-to-date bounds
from an explicit reporting date, with the corresponding prior period clipped to the
same calendar day. The API exposes those bounds and explicitly distinguishes missing
prior-period activity from a usable recorded comparison; percentage change uses the
absolute prior amount. A straight-line projection is labeled as an estimate from
recorded activity, never as observed spend.

All cashflow aggregate consumers share currency qualification. A scope with mixed,
unknown, unofficial, conflicting-provider, or non-USD currency evidence returns a
structured unsupported-scope response rather than a nominal dollar sum. Successful
object responses carry unverified history and duplicate-account coverage metadata;
array responses retain their existing shapes. Account balances receive a separate
currency guard. No exchange conversion is implied.

The effective SQL view now exposes currency evidence. Refund-only categories are
kept in signed totals and the Sankey response declares when its positive-width
visualization cannot faithfully represent them. Independent CF-02 oracle tests cover
API totals, categories, SQL-view parity, every paginated evidence page, period
boundaries, pending/out-of-scope currencies, zero-row sync history, and negative
comparison denominators.

Integrated verification after CF-05/CF-06: **228 backend tests passed at 86.30%
coverage**; frontend **37 tests passed**, typecheck and production build passed.
CF-07 is complete. CF-08 owns the user-facing presentation of the reporting
qualification and unsupported-scope response; CF-10 remains the independent
adversarial verifier.
