## Acceptance Criteria

- [ ] Income, expense, net cashflow, categories, period summaries, and transaction drill-downs follow the CF-02 accounting contract and agree on contributing rows.
- [ ] Realized totals use posting dates, exclude pending activity, and use the agreed distinction between internal transfers and unresolved candidates.
- [ ] Refund handling is consistent across totals and categories, including later-period refunds and refund-only negative categories; uncertain reimbursements do not silently reduce expense.
- [ ] User category corrections, supported rules, and fallback categories follow one documented precedence and remain stable across sync/recomputation.
- [ ] API results and the effective SQL/dashboard view agree for the same scope. Shared deterministic functions or existing service/query paths express the policy without a second independent money calculation in the client.
- [ ] Existing API/filter paths can retrieve the rows explaining a displayed aggregate, including beyond the first page; optional agents can query those paths without ingesting the ledger.
- [ ] Corrections and new counterpart history update affected historical totals; unsupported mixed-currency aggregation is not presented as a meaningful combined amount.
- [ ] Add parity and edge-case tests with hand-calculated results. Integrate against CF-05/CF-06 before final verification; do not introduce unrelated API or analytics infrastructure.
