## Acceptance Criteria

- [ ] Audit every non-chart React surface that presents an ordinary date, including
  Activity rows/tables, transaction detail, Transfer Detection, Recurring, account
  linking/session copy, and any review/status surface discovered during the audit.
- [ ] Display dates in the current calendar year as `2 Sep` and dates outside the
  current calendar year as `2 Sep, 2025`, using abbreviated English month names and
  no leading zero.
- [ ] Use one shared formatter for the year decision; callers do not recreate
  current-year logic. ISO date inputs and machine-readable API parameters remain
  unchanged.
- [ ] Treat date-only values without UTC/local rollover. Define explicit behavior
  for invalid/missing values rather than showing `Invalid Date`.
- [ ] Chart axes and chart tooltips remain free to use density-appropriate formats
  and are explicitly excluded from the audit's change list.
- [ ] Tests inject or pass a fixed reference date and cover same-year, prior-year,
  future-year, year boundary, leap-day, invalid, and date-only timezone cases
  deterministically.
- [ ] Run focused formatting/component tests, the frontend suite, typecheck, and
  production build; record the audited surface list in the execution log or a
  linked artifact.
- [ ] Make PI-25's deterministic formatting cases pass unchanged; escalate any
  request to redefine their output contract.

## Technical Context

`frontend/src/lib/format.ts::formatDate` currently always calls `toLocaleDateString`
with month/day only. `TransactionRow`, desktop Activity, `AnnotationSheet`,
`routes/transfers.tsx`, and `routes/recurring.tsx` use it, so changing the shared
formatter addresses the known omissions broadly. `routes/add-account.tsx` formats
a timestamp as time-only and should be assessed separately. Calendar heatmap and
other chart-specific functions are exempt.

Suggested role: frontend engineer. Make the reference year injectable or otherwise
clock-controlled in tests instead of asserting against the day the suite runs.
