## Acceptance Criteria

- [x] A category shown in Overview's category comparison is inspectable in the same
  way as the equivalent category shown in Spending.
- [x] Both surfaces construct the Activity destination through one shared path,
  carrying the effective category, `is:spend` semantics, inclusive current-period
  start/end dates, and a stable default sort.
- [x] Overview uses the precise reporting bounds represented by its comparison; it
  does not derive a subtly different period from the browser clock when server
  reporting metadata is available.
- [x] For a hand-checkable fixture containing posted charges, a refund, a pending
  row, an unconfirmed transfer candidate, and a confirmed transfer, each source
  category's current value equals the signed expense contribution of the complete
  Activity population reached through the link.
- [x] Parent/child and exact effective-category behavior is intentional and tested;
  equivalent aggregates on Overview and Spending lead to equivalent transaction
  sets rather than merely similar-looking URLs.
- [x] Links are keyboard operable, visibly identifiable as interactive, preserve
  the configured base path, and retain useful empty/error behavior.
- [x] Add focused component/route and API parity tests and run the frontend tests,
  typecheck, build, and relevant backend accounting/search tests.
- [x] Make PI-13's accepted tests pass without weakening or rewriting their
  contract. Any test change required after acceptance is an escalation.

## Technical Context

`frontend/src/components/finance/CategoryComparison.tsx` already accepts
`getCategoryHref`. `frontend/src/routes/spending.tsx` supplies it; the same component
in `frontend/src/routes/index.tsx` does not. Spending currently owns local
`appHref()` and `activePeriodBounds()` helpers. Activity in
`frontend/src/routes/transactions.tsx` hydrates `category`, `query`, `startDate`,
`endDate`, `sort`, and `order`; `GET /transactions` applies exact category and the
shared `is:spend` search scope. Prefer a small shared drilldown helper over copying
the existing callback. Coordinate its contract with epic 030, which extends the
same path to Sankey and Movers.

Suggested role: frontend/product engineer paired with accounting-test review.

### 2026-09-11 — implementation

Added `frontend/src/lib/categoryDrilldown.ts` as the shared destination builder
for inspectable spending aggregates. It encodes the exact effective category,
`is:spend` query, inclusive bounds, stable date-descending order, and configured
frontend base path in one URL construction path. Spending now uses this helper;
Overview supplies it only when the server-provided current-period bounds are
available, so it cannot derive a competing period from the browser clock.

The existing `CategoryComparison` anchor remains the native keyboard-operable,
visible interaction and its empty/loading/error behavior is unchanged. Sankey
and Movers routes were not changed.
