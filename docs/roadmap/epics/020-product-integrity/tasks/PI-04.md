## Acceptance Criteria

- [x] Store a structured relationship that identifies canonical and duplicate
  records, enforces the PI-03 invariants, and can be queried without parsing notes.
- [x] Marking and reversing are atomic, validated API operations with useful errors;
  both imported transactions remain retained and individually inspectable.
- [x] The duplicate record is excluded once—and only once—from every shared
  financial aggregate and derived financial consumer defined by PI-03; the
  canonical record continues to contribute normally.
- [x] Existing confirmed-transfer, candidate-transfer, refund, effective-category,
  currency, pending, and posting-date semantics remain intact. Similar date/amount
  rows that have no explicit relationship remain fully counted.
- [x] Sync replay, provider modification/removal, relinking, fingerprint restoration,
  and startup orphan cleanup preserve or invalidate the relationship according to
  the accepted contract without attaching it to an unrelated row.
- [x] Idempotent schema evolution works for an existing SQLite database and has a
  documented safe rollback/recovery path; no production data is used for testing.
- [x] Add test-first, hand-checkable regressions covering totals, category spend,
  Sankey, recurring/review eligibility, search evidence, reversal, lifecycle, and
  two legitimate identical-looking charges. Record red/green commands and results.
- [x] Make PI-15's accepted accounting/lifecycle tests pass unchanged. Escalate a
  flawed or incomplete contract rather than editing its tests during implementation.
